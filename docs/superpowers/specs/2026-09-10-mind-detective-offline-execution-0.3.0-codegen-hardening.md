# MIND Detective 0.3.0 Codegen and Contract Hardening

**Status:** normative addendum to `2026-09-10-mind-detective-offline-execution-0.3.0-design.md`  
**Precedence:** where this addendum is more specific, it overrides the earlier wording without changing the approved architecture.

## 1. No third reducer in the API adapter

The portable kernel is not only a Web code-generation source. It is the single implementation source for every operation listed in `mind-detective-local-execution/v1`.

Therefore:

- `CaseController` remains the public Python domain facade and delegates supported operations to the portable kernel;
- `apps/api/mind_detective_api/commands.py` must also delegate supported command semantics to the portable kernel / `CaseController` facade instead of keeping independent command-specific mutation logic;
- `apps/api/mind_detective_api/checklist.py` delegates deterministic proposal/planner semantics to the portable kernel;
- API-layer code may validate Pydantic request shape, map errors to HTTP, and translate transport contracts, but may not reimplement candidate creation, search-check mutation, lifecycle mutation, feedback rules, planner ordering or journal semantics.

A repository boundary test must fail if supported domain transition branches are reintroduced into the API adapter.

## 2. Portable intrinsics, not approximate JavaScript semantics

The code generator must not translate Python behavior to a superficially similar JavaScript built-in when observable semantics can differ.

The portable subset therefore has an explicit allowlisted intrinsic layer. Each intrinsic has:

1. a Python reference implementation;
2. a deterministic TypeScript emission/runtime implementation;
3. cross-runtime fixtures;
4. generator recognition by exact qualified/name identity;
5. fail-closed behavior for an unrecognized call.

Required intrinsics for `v1` include at least:

- deep clone of JSON-compatible values;
- Unicode case folding used by target duplicate normalization;
- Python-equivalent whitespace splitting/collapse used by that normalization;
- deterministic string comparison used by the planner ID tiebreak;
- canonical JSON serialization/hash helpers used by receipts and conformance;
- creation of a stable coded local-execution exception.

### 2.1 Unicode case folding

JavaScript `toLowerCase()` or locale-sensitive lowercasing is not an acceptable replacement for Python `str.casefold()`.

If existing Python semantics require case folding, the generator must emit the required mapping data from the pinned Python runtime/Unicode database or otherwise implement an exactly fixture-certified equivalent. The conformance corpus must include non-ASCII cases that distinguish lowercasing from case folding, not only RU/EN ASCII-like examples.

### 2.2 Whitespace

JavaScript `trim().split(/\s+/)` is not assumed equivalent to Python `str.split()` with no separator. The generator/intrinsic must use the Python whitespace definition represented by committed/generated fixtures.

### 2.3 String ordering

JavaScript default `.sort()` is not assumed equivalent to Python string ordering for arbitrary Unicode strings. Planner tie-breaking must use a generated/certified comparator with Python-equivalent code-point ordering, or the contract must validate the compared identifier alphabet strongly enough that equality is proven by tests. The default choice for `0.3.0` is a certified comparator, not a new restriction on user-derived identifiers.

## 3. Generator semantic identity is part of deployment compatibility

`kernel_sha256` alone cannot prove that the installed Web executor and API agree: a generator change could produce a different artifact from the same Python source.

The embedded and API execution metadata therefore contains all of:

```json
{
  "version": "mind-detective-local-execution/v1",
  "kernel_sha256": "sha256:<64-hex>",
  "generated_sha256": "sha256:<64-hex>",
  "generator_version": "local-execution-generator/v1",
  "case_schemas": ["mind-detective-case/v2"]
}
```

For assistant/network semantic compatibility the client sends:

- `execution_contract_version`;
- `execution_kernel_sha256`;
- `execution_generated_sha256`;
- `execution_generator_version`.

The API compares all four identities to its release metadata before invoking LiteLLM. Any mismatch returns `MD_WEB_EXECUTION_CONTRACT_MISMATCH` before provider invocation.

The metadata endpoint `GET /api/v1/execution/contract` returns the same complete identity.

## 4. Generated artifact integrity

CI must prove all of the following on Python 3.10 and 3.13 where applicable:

- portable AST validator accepts exactly the committed portable kernel/intrinsics;
- generator output is byte-deterministic;
- generated metadata hashes the exact committed/generated bytes;
- regeneration produces zero git diff;
- Python and generated TypeScript pass the complete differential corpus;
- generated artifact contains no `eval`, `new Function`, dynamic remote import, provider SDK reference, clock/random call or network call.

The conformance test is the semantic gate; the source hash and generated hash are deployment identity/integrity gates. Neither substitutes for the other.

## 5. Case creation idempotence

Offline Case creation does not use `CommandEnvelope`, so double-submit safety must be explicit.

The client creates `case_id` and `created_at` before invoking the generated `createCase()` function. IndexedDB insertion is create-only:

- absent `case_id` → atomically insert;
- existing `case_id` with the same canonical creation identity (`case_id`, `item_label`, `created_at`) → return existing Case;
- existing `case_id` with conflicting creation identity → fail with `MD_WEB_CASE_ID_CONFLICT`;
- creation never overwrites an existing Case.

The create button may additionally disable while the transaction is active, but UI disabling is not the idempotence mechanism.

## 6. API compatibility path

`POST /api/v1/case/command` remains available for `0.2.x` clients, but supported `v1` semantics must execute through the same portable kernel/facade. It is a compatibility transport, not a separate reducer.

A `0.3.0` client uses the network command endpoint only when its installed execution contract does not support the requested operation. Such fallback is explicit and must not silently reinterpret a locally rejected command.

## 7. Additional stable requirements

Implementation must trace at least these additional contracts:

- `MD-OFFLINE-REQ-API-01` — API command/checklist adapters contain no independent supported-domain reducer.
- `MD-OFFLINE-REQ-INTRINSIC-01` — Python-specific observable semantics use certified portable intrinsics, not approximate JS built-ins.
- `MD-OFFLINE-REQ-IDENTITY-01` — version, kernel hash, generated hash and generator version all participate in compatibility checks.
- `MD-OFFLINE-REQ-CREATE-01` — offline Case creation is create-only and idempotent/conflict-detecting.
