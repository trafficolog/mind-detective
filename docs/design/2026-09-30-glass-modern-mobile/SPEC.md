# SPEC — MIND Detective, мобильный прототип (SDD)

Источник: trafficolog/mind-detective@main (README, `ru.ts`), MIND Detective Design System (Glass Modern).
Принципы: **DRY** (одно ядро `domain.js`, UI только рендерит), **KISS** (один экран-компонент, localStorage), **YAGNI** (нет аккаунтов, карт, вероятностей, live-ассистента).

## 1. Цель
Локальный мобильный PWA-прототип полного цикла дела: рассказ → подтверждённые сведения → timeline (неизвестные/противоречия) → явный переход в поиск → физические проверки → журнал → закрытие → экспорт/импорт.

## 2. Эпистемические инварианты (нарушение = дефект)
| # | Инвариант |
|---|---|
| I1 | Свободный рассказ хранится дословно, не классифицируется |
| I2 | Сведение появляется только по явному подтверждению пользователя |
| I3 | Неизвестное — допустимое состояние; система не заполняет пробелы |
| I4 | Противоречия показываются, не разрешаются автоматически |
| I5 | Переход в Search — только явное действие |
| I6 | Проверка = место + способ + результат; повтор — отдельная запись |
| I7 | Никаких вероятностей/процентов; только конечные счётчики |
| I8 | Ассистент — только исследование; предложение не факт |
| I9 | Закрытое дело неизменяемо |
| I10 | Приложение не получает доступ к галерее, файлам и облакам: источники проверяет пользователь, в деле — только названия и результаты |

## 3. Модель данных (`mind-detective-proto/v1`)
`Case {id, num, title, kind: physical|digital, mode: reconstruction|search, paused, outcome{kind: found|closed, where, at}|null, freeAccount, statements[], events[{title,time,precision}], zones[], checks[{place,method,result,note,repeat,time}], created, updated}`.
Экспорт — JSON `{schema, case}`. Это упрощённая проекция; каноническая схема продукта — `mind-detective-case/v2`.

## 4. Экраны
Splash → Онбординг → Дела (фильтры, CaseCard) → Новое дело → Дело: Реконструкция / Поиск / Журнал (нижняя навигация) → шторки: сведение, событие, место, проверка, закрытие, меню дела, подтверждение удаления → Настройки (приватность, экспорт/импорт, ассистент research-only, сброс).

## 5. Правила вывода
- Timeline сортируется по времени; события без времени — в конце.
- Противоречие: ≥2 события с **одинаковым точным** временем и разными названиями.
- Прогресс: зона считается проверенной, если последняя проверка ≠ «неполная».
- Следующая проверка: первая непроверенная зона списка (без ранжирования по «вероятности»).

## 5a. Ассистент и голос
- Ассистент включается в настройках, по умолчанию выключен. Запрос — только по кнопке «Предложить следующий шаг».
- Модели уходит минимальный контекст (без свободного рассказа и гипотез). Ответ проходит детерминированный guard: только JSON, без вероятностей/утверждений о местонахождении, без повтора проверенных зон.
- Сбой, таймаут или отклонённый ответ → локальное предложение из контрольного списка (`source: fallback`). При выключенном ассистенте — тот же локальный путь.
- Предложение — только исследование: «Добавить в список» создаёт зону, «Ответить» открывает форму сведения с пустым текстом. Ничего не становится фактом без действия пользователя.
- Сервер — **n8n** (docs/n8n): приложение хранит только адрес n8n и токен webhook; ключи моделей и Whisper — в n8n Credentials. `md-propose` получает только prompt с минимальным контекстом, `md-transcribe` — запись голоса. Без сервера: локальный контрольный список и распознавание речи браузером.
- Голосовой ввод в больших полях (рассказ, сведение, заметка, название дела). Текст дописывается в поле и сохраняется только по кнопке.

## 5b. Типы дел
- `physical` — вещь: места, способы «Осмотрел / Руками / С фонарём / Открыл / Сдвинул / Спросил».
- `digital` — фото, видео, файл: источники (устройство → приложение → папка/альбом), способы «Поиск по названию / Фильтр по дате / Просмотрел папку / «Удалённые» / Переписка / Спросил».
- Один движок: различаются только словарь (`vocab`) и набор способов (`methodsFor`). Смыслы — `docs/MEANING.md`.

## 6. Вне объёма (YAGNI)
Аккаунты, облако, фото, карты, live-ассистент, English, push, сервис-воркер (в прототипе не реализован).
